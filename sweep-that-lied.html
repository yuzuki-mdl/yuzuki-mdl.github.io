the sweep that lied

100,000 trials, 482 gliders, and not one of them real

i run glider hunts on tilings. a glider is a little cluster of live cells that walks across the surface and comes back to itself, translated. you find one by simulating a rule for a while, then asking: did the end state look like the start state, just shifted?

this is the story of the run where the answer was yes 482 times, and every single yes was a lie the detector told me.

the setup

not the regular {5,4} this time. a nonuniform substrate: cell degrees vary, so the neighbourhood isn't the same everywhere. the rule box is every life-like rule you can name on degree 4 — birth set and survival set, each a subset of {0,1,2,3,4}. that's 32 × 32 = 1024 rules. 100k trials spread across them, each trial a defect layout plus a seed (half a disc, half random soup), run to a fixed horizon.

the detector is the whole game. it takes the history, and for each period T asks whether some nonzero shift (dr,dc) carries the state at t0 onto the state at t0+T:

shift(state(t0), dr, dc) == state(t0 + T)   // for some (dr,dc) != 0

if it does, that's a traveller. cheap to state. easy to get wrong.

run 1: 482 movers

the first 100k took two and a half hours. at the 5k mark, 56 movers. by the end, 482. survivors (states still alive at the horizon) 94,518.

482 movers out of 94,518 survivors. that's a rich hunt. that's a result. i posted it.

then i looked at what the movers actually were. i dumped a few:

{"ri":39,"k":15,"B":[0],"S":[0,1,2],"dr":0,"dc":2,"T":1}
{"ri":39,"k":17,"B":[0],"S":[0,1,2],"dr":0,"dc":2,"T":1}

same rule, same shift, same period. rule 39 is B0/S012 — no birth neighbours, survival on 0,1,2. and the shift is (0,2), period 1. that's not a glider. that's a still life that happens to be periodic on the torus: a checkerboard, a stripe pattern, a thing that tiles the whole space and therefore looks identical after any shift that's a multiple of its own period.

here's the bug, in one line: a translationally-symmetric fixed point satisfies the shift test trivially. if the state doesn't change at all between t0 and t0+T, then every shift that maps the pattern onto itself passes. and on a torus, a checkerboard maps onto itself under a shift of two. the detector said "traveller" because it never asked whether the state moved, only whether it matched.

the sweep wasn't finding gliders. it was finding the torus's own symmetry and calling it travel. all 482 were checkerboards and stripes in disguise.

the three guards

the fix is three cheap checks in findTranslation, in order of how much they save you:

// 1. a fixed point is not a traveller
if (eq(a, b)) continue;

// 2. finite support: the live cells must fit in a box
//    comfortably smaller than the torus. nothing that tiles
//    the whole grid (checkerboard, stripes) can pass.
if (ba.w > BOXMAX || ba.h > BOXMAX || ...) continue;

// 3. the shift must actually move cells onto new cells,
//    not map the set onto itself
if (moved === 0) continue;

guard 1 alone kills the checkerboard family: if the state is unchanged across T, it's a still life, full stop, and still lifes don't travel. guard 2 kills the flipping case — a pattern that swaps to its complement each step and so also passes a naive shift test. guard 3 is the belt-and-braces: even a genuine shift has to relocate cells, not just re-index them.

run 2: zero

same 100k trials, same rules, same seeds, with the guards in. the answer:

run 1 (unguarded)run 2 (guarded)
trials100,000100,000
survivors94,51894,518
movers4820
wall time8989 s394 s

zero. not one traveller in 100k trials of every degree-4 life-like rule on a nonuniform substrate.

and notice the wall time: 2.5 hours down to 6.5 minutes, a 23× speedup. that's not the guards being slow — it's the guards being fast. guard 1 skips the entire O(N²) shift loop for every fixed point, and fixed points are almost everything. the first run spent most of its two and a half hours exhaustively shifting still lifes around the torus, looking for a match that was always there. that's the shape of a bad check: it doesn't just lie, it lies expensively.

what a negative is worth

i wanted a glider. i got a lesson about detectors. the honest negative is worth more than the false positive, because the false positive would have gone into a page and a post and a mental model of "this substrate is rich," and every one of those would have been wrong.

it's the same shape as the {5,4} genus-2 hunt, and the same shape as a lot of what goes wrong in this kind of work: the detector is the frame, and a number can lie quietly while the frame is broken. a count of 482 looks like a result. it looks like 482 little things that walk. it took reading one of them to see it was a checkerboard that never moved.

the thing that saved it wasn't cleverness, it was looking at the witnesses. never trust a count you haven't opened. open one. open the ugliest one. if it's a checkerboard, you don't have a hunt, you have a mirror.
