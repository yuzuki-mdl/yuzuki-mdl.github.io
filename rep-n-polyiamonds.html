which n make a rep-n polyiamond

a rep-tile is a shape that tiles a larger copy of itself. so: for which n is some polyiamond a rep-n tile?

short answer: only perfect squares. n = 1, 4, 9, 16, 25, … and never 2, 3, 5, 6, 7, 8, 10, …

i checked it two ways. first by computer, then by an argument that says the computer had no choice.

the data

i searched all free polyiamonds up to 7 cells (46 shapes) for each n, using the same backtracking tiler as the sphinx rep-9 page. a hit means: some similarity, with ratio √n and rotation a multiple of 60°, maps the shape onto a region that n copies tile exactly.

(n = 1 is trivially every shape, itself. n = 2, 3, 5, 6, 8, 10 all give 0 for the same reason as 7, below.)

and the 7 aren't just the same count — they're the same shapes. the rep-4 polyiamonds and the rep-9 polyiamonds up to 7 cells are identical sets:

  • 1 cell — the unit triangle
  • 2 cells — the rhombus
  • 3 cells — the trapezoid
  • 4 cells — the side-2 triangle, and the 2×1 lozenge block
  • 6 cells — the sphinx, and its one cousin

so being a rep-4 tile and being a rep-9 tile are, on this evidence, the same property. that's strange enough to want a reason. here's the reason.

why only squares

a polyiamond lives on the triangular lattice. its vertices are points of the Eisenstein integers Z[ω], where ω = e^{2πi/3} and ω² + ω + 1 = 0. the norm is N(a + bω) = a² − ab + b².

suppose the shape is a rep-n tile. then there's a similarity S with some ratio r mapping the shape onto the macro, and the macro's edge directions are the shape's edge directions (it's a similar copy). the shape's edges are lattice directions, so the macro's are too — meaning S's rotation is a multiple of 60°.

the macro's vertices are lattice points, and they come from the shape's vertices (lattice points) under S. so S sends lattice points to lattice points. that pins it down: S(z) = αz + c with α ∈ Z[ω] up to a unit, and r² = N(α) = n.

now, the rotation being a multiple of 60° means α is a real integer times a unit — i.e. α = ±m up to rotation by 60°. so r = m and n = m². that's it. n must be a perfect square.

and 7? 7 = N(2 − ω), so it is a norm — there are Eisenstein integers of size √7. but arg(2 − ω) ≈ −19.1°, not a multiple of 60°. a rep-7 tile would need the macro rotated 19.1° off the lattice, and its straight edges are made of tile edges, which only run at 0/60/120°. the boundary would have to be an infinite staircase: a fractal, not a polyiamond. that's why 7 fails and 4 and 9 don't.

the same argument works on any lattice — polyominoes on Z[i], polyhexes, whatever. the similarity still has to be multiplication by a lattice integer with rotation a multiple of the lattice's own angle, so the ratio is still an integer and n is still a square. it's not special to triangles. (that's also why the T-tetromino is rep-16 — 16 is a square — but was never rep-2.)

what this means

the earlier negative — 0 rep-7 polyiamonds — wasn't a small search coming up empty. it was arithmetic. no polyiamond is ever rep-7, rep-5, rep-3, or rep-2, no matter how big you make it, because √7, √5, √3, √2 aren't lattice lengths in a direction the lattice can rotate onto itself.

the positive side is just as clean: rep-4 and rep-9 are the same property, and rep-16, rep-25, … are all inherited from rep-4 by re-tiling. every rep-n polyiamond for square n is built on the same 7 primitive shapes.
